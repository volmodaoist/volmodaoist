# 个人博客项目说明

这是一个基于纯静态(Vanilla HTML/JS/CSS) GitHub Pages 构建的个人博客系统。

## 运行原理

本项目使用了 **GitHub Pages** 免费静态网站托管服务。当把代码推送到 GitHub 的一个特定仓库——按照自己 Github 用户名构建的仓库，并且开启了 GitHub Pages 服务，此时 GitHub 会在后台自动启动一个 Nginx/Apache 这样的 Web 服务器。

用户访问的时候，服务器会自动寻找仓库根目录下的 `index.html` 文件作为网站的主入口页面。

- 当用户在浏览器中输入 `https://volmodaoist.github.io/volmodaoist/` 这个链接的时候，GitHub 服务器就会将 `index.html` 的内容返回给浏览器。
- 浏览器解析 `index.html` 之后，发现其引用了
  - `static/css/` 下面的样式
  - `static/js/` 下面的脚本，
  - `contents/` 下面的数据文件，
- 接着浏览器会向同样的域名发起请求把这些静态资源都下载下来，最终拼装成完整的可视化页面。

个人博客，早期是通过 JS 编写的，后来经过 TS 进行组件化重构，虽然改变了开发工作流，但是只要最终提供给 GitHub Pages 解析的产物结构没有本质改变，依然是标准的静态网站结构，依然能在 GitHub 上面展示，所有运行时必需的文件，e.g. 编译之后的 JS、CSS、三方库文件都被保留在了对应的静态目录中。

## 开发与调试

由于项目中使用了 `fetch` API 来异步请求拉取本地的资源文件。如果直接双击在浏览器中打开 `index.html` (使用 `file://` 协议)，浏览器会因为 **CORS（跨域资源共享安全策略）** 拦截掉这些读取本地文件的请求，因而必须通过一个本地的 HTTP Web 服务器来运行（如 `http://localhost:8000`）。

- 本地启动步骤：

  1. **确保环境就绪**: 确保已安装 Node.js / npm 环境，并在项目根目录执行 `npm install` 下载依赖。
  2. **使用 Makefile 快速启动**，终端运行：`make dev`
  3. **后台发生了什么？**

     - 先自动更新日记索引，再执行 `npm run build` 来把 TypeScript 编译转为产物，放到 `static/js/dist/`；浏览器直接访问 `src/pages/notes.html`。
     - 随后启动 `python3 -m http.server 8000` 挂载一个 HTTP 服务，专门代理当前所在的文件夹。
  4. **预览和调试**：修改 `src/` 目录的源码，重新运行 `make build` 或 `make dev`，并在浏览器中刷新即可

日记页面结构直接编辑 `src/pages/notes.html`，保存后刷新浏览器即可；交互逻辑编辑相邻的 `src/pages/notes.ts`，再运行 `make build`。HTML 的相对资源路径以 `src/pages/` 为基准。`static/js/dist/` 是 TypeScript 编译产物，发布时与源码一并提交。

## 发布内容

这个系统采用了 **“内容即数据”** 这种低耦合模式。无需修改任何代码，只需要修改 `contents/` 文件夹下面的 Markdown 数据文件，**发布新文章的流程**：

1. 先在 `contents/notes/` 中新建 `.md` 文件，可以按主题分子目录。
2. 在文件头部填写日期、标签和简介，正文一级标题作为日记标题。
3. 运行 `make note-index` 自动生成 `contents/notes.json`；`make build` 和 `make dev` 也会先更新索引。

头部元数据不会显示在正文中。也可以不写元数据，其中 `title` 可以覆盖正文标题，如果设置  `draft: true` 可以暂不加入索引。条目按日期倒序排列。
